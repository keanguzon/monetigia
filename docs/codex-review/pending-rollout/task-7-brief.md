## Current source and scope boundary

`InstallmentHistoryGroup.tsx` has one disclosure button, separate row detail/delete buttons and inert collapsed content. Its remaining amount currently sums original live transaction amounts, and its ordinal fallback comes from display descriptions. Keep real purchase date/Date added/Transaction date behavior while using the reviewed snapshot for paid/corrected/remaining debt and authoritative ordinals. `history.ts` groups only explicit `installment_group_id`; `loadHistoryPage` hydrates owned siblings and uses 50-row pagination. Do not infer groups from title, fabricate opening expense rows or replace real history pagination with an incomplete financial query.

Opening rows belong to the complete debt schedule consumer (`DebtScheduleSection`), with Existing debt source label and real due dates. Purchase correction uses real transaction UUIDs; opening correction uses due-row UUIDs. Group/account/fingerprint come from `DebtSnapshot`, never array indices or a client-computed amount hash. An ordinary cash installment group without an owned credit snapshot must keep ordinary transaction behavior and cannot offer debt correction. Paid history remains visible even when remaining is zero.

The sole write is `submit({kind:'correct_debt_rows', accountId, rowIds, fingerprint})`; no transaction quote, `delete_transaction` loop or direct delete/update. Result remains `{operationId,transactionIds:[],replayed}`. Use exact remaining decimal text and checked centavos for the selected sum.

New pure selection API:

```ts
export type DebtSelectionState = { active: boolean; selectedIds: string[]; anchorId: string|null };
export function reconcileDebtSelection(state: DebtSelectionState, eligibleIds: string[]): DebtSelectionState;
export function toggleDebtSelection(
  state: DebtSelectionState, orderedEligibleIds: string[], rowId: string, shift: boolean
): DebtSelectionState;
```

IDs are unique and retained in visible canonical order. Reconcile intersects with current eligible IDs and clears a missing anchor. Plain checkbox toggle changes that ID and establishes its anchor. Shift selects the inclusive visible eligible range from the existing anchor through target (additive to existing selection); if anchor disappeared, behave as a plain toggle. Paid/zero-remaining/ineligible rows cannot enter the range. No index persisted across refresh/reorder.

`InstallmentSelection` is an accessible toolbar with props `{ active:boolean; selectedCount:number; eligibleCount:number; disabled:boolean; onActivate:()=>void; onExit:()=>void; onSelectAll:()=>void; onDeselectAll:()=>void; onRequestCorrection:()=>void }`. Labels: Select, Done selecting, Select all, Deselect all, Delete selected. Disable delete when count0, pending, reviewed account or missing fresh snapshot. Native labeled checkboxes belong to the actual group rows.

`DebtCorrectionDialog` props are `{ open:boolean; onClose:()=>void; accountId:string; groupId:string; groupName:string; selectedIds:string[]; onSaved:()=>Promise<unknown> }`; it reads current owner snapshot/controller, not an amount prop. At opening, freeze a reviewed confirmation `{rowIds, fingerprint, remainingTotal, count}`. Confirm submits that exact version once. If a fresh snapshot invalidates it before submission, require renewed review rather than silently changing the total. All selected IDs must still belong to the same account/group and have positive remaining.

`DebtHistoryGroup` props are `{ account:DebtAccountSnapshot; rows:DebtDueRow[]; onSaved:()=>Promise<unknown> }`, with one account/group/source enforced by its parent grouping. It renders opening and complete purchase schedule rows from the snapshot without pretending they are transactions. Add `debtState: { account:DebtAccountSnapshot; rows:DebtDueRow[] }|null` to actual `InstallmentHistoryGroup` props; a real purchase group maps by exact accountId/groupId/transactionId. Keep existing detail callback and ordinary unrelated delete callback. Canonical `remainingAmount`, `paidAmount`, `correctedAmount` come from that debtState; do not reinterpret original transaction amount as current debt.
