## Source facts and root-approved target boundary

Transactions store `description`, `installment_group_id`, `purchase_date`, generated `history_date`, amount and actual financial ownership. The real group ID has `(user_id,installment_group_id)` FK to `financial_operations(user_id,id)`. New installment operations persist stable `result.transactionIds` in ordinal order; old proven groups have operation/result provenance but may lack purchase date. `history.ts` groups explicit IDs and strips terminal “(Installment n/count)” for display. Matching text is not group proof, and description suffix is not ownership/ordinal proof.

**Root ruling:** An ordinary ungrouped transaction is edited by transactionId. A grouped installment edits all current live owned siblings by its actual groupId, preserving original ordinal/group/operation provenance. A detail view for a grouped child routes to group edit. Heterogeneous base descriptions require review/stale rejection, never guessed grouping. Opening debt name is `debt_items.name` and has no real transaction description target; naming it remains outside Task 8. Paid/corrected actual purchase transactions can receive text edits without changing payment state. Do not require an active account merely to edit historical text if the owned row remains readable.
